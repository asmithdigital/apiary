The date component enables people to select a date, or a range of dates. See the date validation pattern definition for validation rules.

## Variants

- Significant date (no picker) — for a date that's easily recalled or referenced, e.g. birth date. Max width 282px.
- Choose date (picker available) — for a date within ~6 months, where the day of week may matter. Max width 282px.
- Date range (range picker available) — for a start and end date.

## Principles

- The user must always have ultimate control
- The user must be able to edit with ease
- The cursor must not be hijacked — e.g. jumped to the end of a field or to another field
- The solution must be accessible
- The user must not be forced to enter preceding '0's (e.g. 01) to make a form valid — zero-padding should only happen behind the scenes after submission, never somewhere the user can see it
- The solution must support autocomplete where possible
- The user must not be forced to use a date picker/calendar

## Anatomy

- Day, Month, Year fields
- Picker button (icon)
- Calendar picker — single month view (Choose date) or two month view (Date range)
- Select Year, month navigation arrows, month & year label, weekday labels, days

## Size

- The component should not be stretched to fit a container
- Field sizes are fixed based on the input required, to indicate character limits to the user
- On very narrow screens, fields stack vertically with left alignment

## Typography

- Date label — Semibold/14px | 20px, P2/100
- Field labels — Regular/14px | 20px, P2/100
- Value — Regular/14px | 20px, P2/100
- Description — Regular/12px | 18px, P2/50
- Calendar — month/year label Semibold/14px|20px P2/100; days & years Regular/14px|20px P2/100; weekday labels Regular/12px|18px P2/50

## Character limit

- Day: 2 characters (1 or 2)
- Month: 2 characters (1 or 2)
- Year: 4 characters (must be 4)
- Single-character day/month input should be translated to 01-style format before submission

## States

- Fields: default, hover, active, focus, disabled, value (filled), invalid
- Calendar: default, selected

## Accessibility

- The Date label should be the legend of the field set, with day/month/year as form elements
- Validation errors must be associated with the correct field(s), including via aria-describedby
