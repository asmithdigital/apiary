Tables display structured data in rows and columns for easy comparison and scanning. In a design system, they should be clear, accessible, and responsive, with consistent spacing, readable text, and support for sorting, filtering, and pagination when needed.

## Anatomy

- Clear headers, aligned columns, and consistent cell spacing. Header rows carry labels, with optional sorting or tooltips. Rows support scanning, selection, or actions.
- 1. Label, 2. Title, 3. Paragraph, 4. External link with icon, 5. Paragraph details, 6. Table Container

## Behaviour

- Hover/focus states for clickable rows; prefer buttons/links within cells over full-row clicks
- Sorting with visible icons; dynamic filtering with clear feedback
- Expandable rows for inline detail; pagination or lazy loading with loading indicators and result counts
- Helpful messages for empty/error states
- External links clearly labelled (e.g. with a ↗ icon), open in a new tab with target="_blank" and rel="noopener noreferrer"

## Types

**Bordered table** — spacing/md (24px) padding, 1px solid border using the P2/100 colour token, 4px radius. Best for compact layouts, cards, or modular components where the table should be visually distinct from surrounding content.

**Divider table (borderless)** — spacing/md (24px) padding, no outer border/radius, a 1px P2/50 divider between stacked tables/sections. Best for clean, open layouts like dashboards or lists.

## Accessibility

- Semantic table elements — <table>, <thead>, <tbody>, <th>, <td>
- Descriptive headers using <th scope> to link data cells to their headers
- Keyboard navigation through rows and interactive elements (sorting, pagination)
- Sufficient colour contrast; never rely on colour alone
- Captions or summaries for scrollable/complex tables

## Do

- Use clear, concise headers with consistent alignment
- Use enough padding to avoid clutter; alternate row colours starting S2/30 then P3/100
- Use semantic HTML and support full keyboard navigation
- Include sorting/filtering/pagination for large datasets
- Make tables responsive — horizontal scroll or stacked layout on small screens

## Don't

- Cram too much data into a single table
- Rely on colour alone to convey meaning
- Use non-semantic elements (e.g. <div>) for table structure
- Hide critical information on smaller screens
- Omit a clear empty state when there's no data

## Content guidelines

**Be clear and concise** — Short, descriptive column headers — not vague terms like "Info" or "Data".

**Keep labels simple** — Plain language; only universally-understood abbreviations.

**Align text properly** — Left-align text, right-align numbers for easy comparison.

**Use consistent formatting** — Same date format, currency symbols and decimals throughout.

**Limit text length** — Truncate with ellipses; use tooltips or expandable rows for more detail.

**Avoid overloading** — Prioritise essential content; use progressive disclosure for secondary info.

**Support empty states** — e.g. "No items found. Try adjusting your filters."
