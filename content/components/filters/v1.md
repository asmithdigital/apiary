Filters help users narrow down content by selecting specific criteria. They appear as dropdowns, checkboxes, or toggles, depending on context. Filters should be clear, easy to adjust, and consistently placed for quick access across devices.

## Anatomy

- A label describing the filter category, filter controls (checkboxes, toggles, dropdowns), and a clear/reset button. Active filters show as tags or chips for easy review and removal. Layout may adjust to a panel, drawer, or dropdown on smaller devices.
- 1. Filter name, 2. Clear all filters, 3. Pull-down menu
- Price range filter — 1. Slider selector, 2. Price parameter
- Checkbox filter — 1. Filter label, 2. Ticked/unticked label, 3. Show all

## Accessibility

- Range filter: keyboard-accessible slider (arrow keys, tab), visible focus indicators, clear "Minimum"/"Maximum" labels programmatically linked for screen readers
- ARIA attributes on the slider — aria-valuemin, aria-valuemax, aria-valuenow, aria-label
- Sufficient colour contrast; error messaging announced via aria-live where needed
- Touch targets meet the minimum recommended size for mobile

## Do

- Use clear and descriptive labels
- Make filters accessible via keyboard and screen reader with ARIA attributes and visible focus indicators
- Keep filters responsive with touch-friendly controls
- Display active filters clearly and allow easy removal
- Group related filters logically; validate input with accessible error messages

## Don't

- Rely on colour alone to communicate filter states
- Hide filter labels or make users guess their purpose
- Overwhelm users with too many unorganised filter options
- Force a strict filtering order
- Design filters that are difficult to use on smaller screens

## Content guidelines

**Use clear labels** — Filter names must be simple, direct, and clearly describe what they do.

**Be specific** — "Price Range" or "Kilometres", not vague terms like "Amount".

**Keep it concise** — Short labels and options; extra detail goes in tooltips or help text.

**Match user language** — Avoid internal terminology users won't recognise.

**Use consistent capitalisation** — Sentence case across all filter labels and options.

**Group related options** — e.g. "Vehicle Type" or "Coverage Level" categories.

**Provide default values carefully** — Only pre-select if it improves the experience — never force confusing defaults.

**Show active filters clearly** — Displayed with an easy way to remove or adjust them.

**Avoid jargon** — Filters should feel accessible regardless of technical knowledge.

**Support error prevention** — Hint text, examples, or tooltips for filters needing user input (sliders, numeric fields).
