Radio buttons let users select one option from a group. Only one can be chosen at a time, and selecting a new option deselects the previous one. Each button should have a clear label and be grouped with a descriptive heading.

## Variants

- Desktop, simple Yes/No: radios can be horizontally stacked; combined width 282px with 24px horizontal padding between them
- Desktop, Yes/No/longer options: radios can be vertically stacked, full width
- Mobile: vertically stacked and full width

## Anatomy

- A radio button consists of a circular input icon (filled when selected, empty when not), a label describing the option, and is grouped with other radio buttons under a group label or fieldset title. Supports keyboard navigation, focus states, and mutually-exclusive selection.
- 1. Radio Button Icon, 2. Field Label

## Size

- Vertical spacing between radio buttons — 12px
- Space above the group label — 24px
- Horizontal layouts — at least 16px between options
- Spacing between buttons and helper/error text — 8px

## States

- Default — unselected, hollow circular icon with a readable label, fully interactive
- Focus — a visible focus indicator (e.g. a ring/outline) appears when navigated to via keyboard
- Selected — a filled inner circle appears; selecting one automatically deselects any other option in the group
- Disabled — greyed out or reduced opacity, cannot be clicked, focused, or keyboard-navigated
- Error — the whole group (not just one button) shows a red border/icon/underline plus a clear error message nearby

## Accessibility

- Keyboard accessible with arrow-key navigation between options
- Group using a semantic &lt;fieldset&gt; with a &lt;legend&gt; for context
- Use appropriate ARIA roles for custom components; visible focus indicators
- Screen readers should announce the group name, selected option, and total number of choices

## Content guidelines

**Use clear, descriptive labels** — Describe the actual value or action, not vague terms like "Option 1".

**Use sentence case** — "Email notifications", not title case.

**Group with a meaningful question or prompt** — e.g. "How would you like to be contacted?" — improves context and screen reader accessibility.

**Limit the number of options** — No more than 5–7; use a dropdown for longer lists.

**Make options mutually exclusive** — If multiple selections are possible, use checkboxes instead.

**Avoid default selection unless necessary** — Preselecting only when there's a clear benefit or it matches a user's prior input.

**Avoid "Other" without clarification** — Pair it with a text field so users can add detail.

**Support accessibility with fieldsets and legends** — Wrap groups in semantic &lt;fieldset&gt;/&lt;legend&gt;.

**Be consistent in wording and structure** — Keep phrasing parallel across labels.

**Use tooltips or help text sparingly** — Only when the label truly can't stand alone.

## Real token names (documentation)

- Gap between radio icon and field label — spacing/sm
- Radio horizontal — top/bottom/left/right padding all spacing/sm
