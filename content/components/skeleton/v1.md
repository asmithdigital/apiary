A skeleton acts as a placeholder for content, usually while it loads, to improve the perceived loading experience. Instead of a blank screen or a traditional spinner, it shows a placeholder layout that mimics the structure of the content that will eventually load.

## Anatomy

- Darker grey bars indicate where content will load, regardless of background. A blank skeleton matches the dimensions of the component it represents; a text skeleton suits text with no background; a text-on-background skeleton suits larger text-in-container components; a skeleton with an image suits card/tile components.

- Text — 1. Title and content skeleton
- Text on background — 1. Background, 2. Skeleton text
- With image — 1. Skeleton card image, 2. Skeleton text on background

## Size

- Padding top/bottom — 24px
- Padding left/right — 24px
- Gap — 6px

## Behaviour

- A "shimmer effect" — a subtle gradient overlay moving left to right — animates during loading

## Types

**Sizing rule** — The skeleton's width and height should precisely match the content, component, or image it represents, for a seamless transition once loading completes.

## Accessibility

- Use semantic HTML that gives context to assistive technologies
- Use aria-busy="true" to signal loading
- Provide meaningful text alternatives/descriptions indicating content is loading
- Manage keyboard focus correctly — never trap or lose it within a skeleton
- Inform users if loading will take a long time, with a progress indicator if feasible
- Respect reduced-motion preferences
