Icons are essential visual elements that support navigation, actions, and communication across our digital products. They provide quick, intuitive cues that help users interact efficiently.

Icons act as quick visual cues that enhance usability, reinforce meaning, and support consistency across our digital products. In Apiary, they appear in navigation, buttons, alerts, inputs, and more.

## Where things stand today

Currently, icons are used in several ways:

- Designers copy and paste individual icons into squad specs from a shared Figma file
- Some components embed icon fonts (such as Font Awesome) via text layers
- There are no defined sizes, spacing rules, or standard icon components

_We're moving to a shared set of reusable, fixed-size icons that can be used consistently across all components. This will improve accessibility, reduce manual design work, and streamline the developer experience._

## Use icons to

- Reinforce meaning (e.g. a warning icon in an alert)
- Represent an action (e.g. a plus icon for "Add")
- Aid quick scanning and enhance navigation (e.g. icons in menus)

## Avoid using icons when

- They serve only as decoration — every icon should have a clear purpose
- They are used without accompanying text, unless the meaning is universally understood

## Icon sizes (standardising to two)

- Small — 16×16px: tags, form fields, compact UI, inline with text
- Large — 24×24px: buttons, alerts, modals, empty states, banners, standalone contexts

_Token names: icon-sm (width/height size-sm), icon-lg (width/height size-lg). Designers should size icons manually to fit these values until components are updated._

## Placement and alignment

- Icons should align to the layout grid and follow existing spacing rules
- Maintain clear padding between icons and adjacent text or elements
- When placed next to text, ensure vertical alignment to the text baseline
- Icons should be optically centred within containers

## Icon sets

- Component-based icons (preferred) — a reusable Figma library with fixed sizing
- Typography-based icons (legacy) — icon fonts (e.g. Font Awesome) via text layers, still permitted in some dynamic text use cases

## Usage in components

Icons must follow component layout and spacing rules. Use icon variants from the Figma component library. Avoid resizing or detaching icons to maintain consistency.

## Using the Icon component in Figma

Use the Icon Set component in Figma to ensure consistency and scalability. Select icons from the dropdown or variant picker — avoid pasting SVGs or detaching layers.

## Content guidelines

- Use recognisable, platform-appropriate icons
- Don't invent new symbols — rely on system-standard or widely accepted visuals
- Pair icons with descriptive text unless the icon is universally understood (e.g. close, search)

## Do / Don't

- Do: use predefined 16px or 24px sizes — Don't: use random or resized icons
- Do: use the Figma icon component — Don't: paste standalone SVGs
- Do: maintain padding and alignment — Don't: eyeball icon placement
- Do: ensure functional icons meet colour contrast requirements — Don't: use low-contrast icons for functional purposes
