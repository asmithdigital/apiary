Design tokens are the core building blocks that define and unify the visual style of our products, enabling consistency and scalability across design and development.

## What is a design token?

Design tokens are named variables that store design decisions such as colours, typography, spacing, and other style properties. Instead of hardcoding values directly into code or design files, tokens provide a functional name that describes the purpose of the style (e.g. color-primary, spacing-small), abstracting the actual value.

## Why use design tokens?

- Maintain consistency — tokens ensure all teams use the same colours, fonts, spacing, and other styles
- Simplify updates — changing a token value updates all instances where it's used
- Bridge design and development — tokens serve as a shared language between designers and developers
- Scale efficiently — style changes propagate quickly and reliably across multiple platforms and components

## How we use design tokens

While we are currently in the process of defining and implementing design tokens, our goal is to provide a global set of tokens accessible by both design and development teams. Once established, developers will reference tokens directly from a shared repository in formats compatible with their codebases (e.g. JSON).

## Types of design tokens

- Colour — brand colours, semantic colours (success, error), UI-specific colours
- Typography — font families, sizes, weights, line heights, letter spacing
- Spacing — margins, paddings, layout-related dimensions
- Sizing — widths, heights, other dimension properties
- Opacity — transparency levels for UI elements
- Borders — widths, styles, colours for borders
- Shadow/Elevation — depth and shadow effects
- Animation/Transition — timing, duration, easing for UI animations
